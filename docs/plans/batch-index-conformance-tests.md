# Plan: BATCH Index Conformance & Unit Tests

## Goal

Add comprehensive test coverage for the msg_id 0x07 (RPC Batch Index)
protocol across all three test tiers: serde conformance, peer conformance,
and internal unit/cross-language tests.

## Context

The BATCH index implementation landed in `ts/src/unity/rpc.ts`,
`ts/src/unity/server.ts`, `ts/src/unity/client.ts`,
`protocol/unity_protocol.py`, `protocol/unity_server.py`, and
`protocol/unity_client.py`. Only 5 TS unit tests exist for BATCH
encode/decode. No conformance tests, no peer tests, no Python unit tests,
no cross-language golden tests.

## Changes

### Tier 1 — Serde Conformance (2 new categories)

#### `batchIndexEncode` (encode a BATCH 0x07 message)

**Generator** (`conformance/generators/serde/batch_index_encode.py`):
- Input: `{ methodName, methodIndex }`
- Preset tests: RPC_Int idx=0x60, RPC_Float idx=4, RPC_Void idx=2,
  RPC_String idx=126 (max 7-bit), RPC_Alpha idx=0 (min)
- Random tests: pick random method, random index 0-126

**Validator** (`conformance/validators/serde/batch_index_encode.py`):
- Encode with Python reference, compare `dataHex` and `bitLength`

**Reference implementer** (`conformance/reference_implementer.py`):
- `process_batchIndexEncode(inp)`: call `encode_batch_index`, return
  `{ dataHex, bitLength }`

**TS runner** (`ts/scripts/conformance-runner.ts`):
- `batchIndexEncode` handler: call `encodeBatchIndex`, return
  `{ dataHex, bitLength }`

#### `batchIndexDecode` (decode a BATCH 0x07 message)

**Generator** (`conformance/generators/serde/batch_index_decode.py`):
- Input: `{ dataHex, bitLength }` (generated by encoding with Python ref)
- Preset: same methods as encode presets
- Random: encode random method+index, emit the hex

**Validator** (`conformance/validators/serde/batch_index_decode.py`):
- Decode with Python reference, compare `methodName` and `methodIndex`

**Reference implementer**:
- `process_batchIndexDecode(inp)`: call `decode_batch_index`, return
  `{ methodName, methodIndex }`

**TS runner**:
- `batchIndexDecode` handler: call `decodeBatchIndex`, return
  `{ methodName, methodIndex }`

#### Registry updates

- `conformance/generators/serde/__init__.py`: add both generators, count → 32
- `conformance/validators/serde/__init__.py`: add both validators, count → 32
- `conformance/reference_implementer.py`: add both processors
- `conformance/tests/test_all_serde_categories.py`: assertions 30 → 32
- Add `('batchIndexEncode', 'batchIndexDecode')` to `ROUNDTRIP_PAIRS`

### Tier 2 — Peer Tests (new scenarios in `conformance/generators/peer/rpc.py`)

Add scenarios to the existing RPC peer test generator:

1. **Subsequent-use via BATCH exchange**: Client sends RPC_Int twice.
   First is first-use, second should still arrive (via BATCH-negotiated
   subsequent-use). Verify both received with correct params.

2. **Bidirectional BATCH exchange**: Server sends first-use RPC_Int to
   client, client sends first-use RPC_Int to server. Then both send a
   second RPC_Int. All four received correctly.

3. **Multiple methods BATCH**: Client sends first-use for RPC_Int,
   RPC_Float, RPC_String, then sends each again. All 6 received.

### Internal Tests

#### Python unit tests (`tests/test_unity_protocol.py`)

- `test_batch_index_encode_decode_roundtrip`: encode then decode for
  multiple methods, verify symmetry
- `test_batch_index_decode_rejects_wrong_msgid`: non-0x07 returns None
- `test_batch_index_decode_rejects_short`: too-short returns None
- `test_batch_index_method_index_override`: `encode_rpc_subsequent` with
  explicit `method_index` kwarg uses override, not METHOD_INDEX_MAP

#### Cross-language golden (`tests/test_cross_conformance.py`)

- Add `GOLDEN_BATCH` dict with golden hex values generated by TS
  `encodeBatchIndex` for RPC_Int/idx=0x60 and RPC_Void/idx=2
- `test_batch_index_encode_matches_ts`: Python encode matches golden hex
- `test_batch_index_decode_matches_ts`: Python decode of golden hex
  produces expected method+index

## Exit Criteria

1. `python3 -m pytest tests/ -x` passes (all existing + new tests)
2. `npx vitest run` passes (all existing + new tests)
3. Conformance category count is 32 in all registries
4. `test_all_serde_categories.py` passes with 32 categories
5. Peer RPC tests pass including new BATCH scenarios
6. Cross-language golden values match between TS and Python
